# Java 接口文档编写 Skill

## 工作流程

按以下四步执行，不要跳步：

1. **解析接口信息**：从用户提供的 Controller 代码、方法签名、DTO 类、业务描述中提取接口路径、请求方式、参数、返回值。
2. **确定接口分类**：判断是增删改查/分页/上传下载/批量操作/复杂业务接口，选择对应模板结构。
3. **按规范编写文档**：严格遵循下方"核心规范"，每个字段必须标注类型、必填、约束、说明。
4. **自检清单**：写完后逐条对照"自检清单"检查，缺项立即补全。

## 核心规范（必须遵守）

### 基础信息
每个接口必须包含：接口名称、路径、请求方式、所属模块、接口说明、鉴权方式、幂等性、限流规则。缺少任何一项视为不合格。

### 请求参数
- 严格区分四类参数并分开列表：Header / Path（PathVariable）/ Query（RequestParam）/ Body（RequestBody）。
- 每个参数必须标注：参数名、类型、必填（是/否）、约束（长度/范围/正则/枚举）、说明。
- 枚举参数必须列出全部取值及含义（如 `0=禁用,1=正常`），禁止只写"状态"。
- 时间参数必须标注格式（`yyyy-MM-dd` 或 `yyyy-MM-dd HH:mm:ss`）。
- 选填参数需标注默认值。
- 敏感字段（密码、手机号、身份证）需标注加密/脱敏规则。

### 响应参数
- 全局统一响应体：`code` / `msg` / `data` / `timestamp`，禁止接口各自定义返回结构。
- data 内每个嵌套字段、子对象、集合元素都必须逐一说明类型和含义。
- 集合空数据返回 `[]`，不返回 `null`，需在文档中注明。
- 分页接口固定结构：`total` / `pages` / `current` / `size` / `rows`。

### 错误码
- 区分系统通用码（200/400/401/403/404/409/429/500）和业务自定义码（10000~99999，按模块分段）。
- 每个接口必须列出该接口可能返回的所有业务错误码及触发场景。
- 错误码全局唯一，不重复。

### 示例
- 每个接口必须提供：完整请求示例（JSON/参数）+ 成功响应示例。
- 高频错误场景补充异常响应示例。
- 示例数据要真实合理，禁止用 `xxx` / `string` 占位。

### 业务说明
- 复杂接口（下单、退款、审核、状态流转）需补充：前置条件、执行逻辑、后置影响、幂等规则。
- 标注接口调用顺序依赖（如"先调用获取验证码接口"）。

## 自检清单（写完逐条核对）

- [ ] 接口基础信息8项齐全（名称/路径/方式/模块/说明/鉴权/幂等/限流）
- [ ] 四类参数分开列表，无混淆
- [ ] 所有参数标注了类型、必填、约束、说明
- [ ] 枚举值全部列出并注明含义
- [ ] 时间格式已标注
- [ ] 响应体遵循全局统一结构
- [ ] data 内所有嵌套字段均有说明
- [ ] 分页接口使用标准分页结构
- [ ] 列出了该接口所有业务错误码
- [ ] 有完整请求示例和成功响应示例
- [ ] 复杂接口补充了业务逻辑说明
- [ ] 无 `xxx` / `string` 等无意义占位数据

## 输出要求

- 默认输出 Markdown 格式，表格清晰，代码块标注语言。
- 如果用户要求适配 Swagger/Knife4j，同步给出 Java 注解代码示例（@Api、@ApiOperation、@ApiModelProperty 等）。
- 如果用户只提供了方法签名或 DTO 类，先基于代码推断补全，再标注需要用户确认的业务字段（如枚举含义、业务规则）。
