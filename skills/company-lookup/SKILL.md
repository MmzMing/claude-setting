# 企业速查 Skill

## 核心原则

1. **不凭记忆作答**。所有事实必须来自本次会话内的 WebSearch / WebFetch 结果。
2. **每条事实标注来源 URL**。无法溯源的信息不写入报告。
3. **数据冲突时多源对比,不擅自合并**。例如注册资本在不同源不一致,全部列出。
4. **明确标注信息缺口**。拿不到就写"未获取",不要编。
5. **重名公司必须先确认**。中国同名公司极多,开工前若用户只给了简称,先用一次 WebSearch 列出候选,让用户选定具体哪家(地区/法人/统一社会信用代码任一锁定)。

## 输入

- **必填**:公司名或股票代码或统一社会信用代码
- **选填**:查询维度(默认六项全查)、地区限定

## 查询流程

### Step 0 - 公司锁定(若有歧义)

```
WebSearch: "{公司名} 工商 注册"
→ 列出前 3 个候选(全称 + 地区 + 法人) → 请用户确认
```

### Step 1 - 工商基础

主搜索源(传给 WebSearch 的 `allowed_domains`):
- `tianyancha.com`
- `qcc.com`
- `qixin.com`
- `gsxt.gov.cn`(权威但常拿不到)

抓取目标字段:
- 公司全称、统一社会信用代码、注册号
- 法定代表人、注册资本、实缴资本
- 成立日期、营业期限
- 注册地址、企业类型
- 经营范围(原文摘录,不做概括)
- 参保人数、最近年报年份

### Step 2 - 股东与对外投资

同上数据源。抓取:
- 前 5 大股东(姓名/公司、持股比例、认缴金额)
- 实际控制人/最终受益人
- 对外投资公司清单(前 10 家,带持股比例)
- 关键人员(高管/董监高)
- 分支机构数量

### Step 3 - 主营业务

数据源按优先级:

1. **官网**:`WebSearch: "{公司名} 官网"`,拿到域名后 `WebFetch` 抓 "关于我们"/"产品"/"业务" 页
2. **上市公司**:`cninfo.com.cn`(巨潮)抓最新年报/招股书的"业务概述"和"主营业务收入构成"
3. **第三方视角**:`xueqiu.com` / `eastmoney.com` 找研报或股票讨论
4. **侧面验证**:`zhipin.com` / `lagou.com` 找招聘 JD,反推团队和技术栈

输出要点:
- 自述业务(官网/年报原话)
- 收入构成(若上市,列分部占比)
- 主要产品/服务清单
- 客户群体/目标市场
- 第三方对其业务模式的评价

### Step 4 - 上市与财务(仅适用上市公司)

数据源:`cninfo.com.cn`, `eastmoney.com`, `xueqiu.com`, `sse.com.cn`, `szse.cn`

抓取:
- 股票代码、上市板块、上市日期
- 当前市值、PE/PB
- 最新季报/年报关键数据:营收、净利润、毛利率、同比增速
- 近 3 年趋势(向上/向下/震荡)
- 重大公告(最近 6 个月)

### Step 5 - 经营风险

数据源:
- `zxgk.court.gov.cn`(中国执行信息公开网)
- `creditchina.gov.cn`(信用中国)
- 通用 WebSearch: `"{公司名} 失信" "{公司名} 处罚" "{公司名} 诉讼"`

抓取:
- 被执行人记录(数量、金额、案号)
- 失信被执行人("老赖")
- 行政处罚(类型、金额、机关)
- 司法案件(数量、近期典型案件)
- 经营异常 / 严重违法

### Step 6 - 舆情与投诉

**这部分数据普遍残缺,严格执行"能拿多少拿多少+明确标注缺口"。**

#### 6.1 投诉平台(优先)

- **黑猫投诉** `tousu.sina.com.cn` — 用 WebFetch 直接抓搜索结果页
  - 投诉总数、近 30 天数量
  - 完成率/回复率
  - 高频投诉主题(归纳 3-5 个)
  - 列 3-5 条典型投诉标题 + 链接
- **12315 / 消费保** — WebSearch 兜底,数据零散

#### 6.2 社交平台(尽力而为)

| 平台 | 抓取方式 | 预期产出 |
|---|---|---|
| 知乎 | `WebSearch site:zhihu.com {公司名}` | 高,完整问答多 |
| 雪球 | `WebSearch site:xueqiu.com {公司名}`(上市公司) | 中高 |
| 微博 | `WebSearch site:weibo.com {公司名}` | 低,只有索引片段 |
| 看准/脉脉 | `WebSearch site:kanzhun.com {公司名}` | 中,员工视角 |
| 小红书/抖音/B站 | `WebSearch site:xxx {公司名}` | 极低,基本只能列条数 |

输出时:
- 每个平台单独一行,写明"已抓取/部分抓取/未能抓取"
- 抓到的内容归纳为"正面 / 负面 / 中性"三类,各列 2-3 条带链接
- 不要把"未能抓取"伪装成"无负面舆情"

#### 6.3 强制警示

报告中"舆情与投诉"章节末尾必须包含:

> ⚠️ 评价类数据存在水军、差评攻击、幸存者偏差,以及平台反爬导致的样本缺失。本部分仅供参考,不构成对该公司的定性判断。

## 工具使用约束

- **必须用 WebSearch + WebFetch**,不准凭模型先验回答任何事实
- WebSearch 优先用 `allowed_domains` 限定到上述权威站点
- 同一事实建议至少两个独立来源交叉验证
- WebFetch 拿不到内容(登录墙/反爬)时,标注"WebFetch 失败:登录墙"并改用 WebSearch 索引片段
- 控制总请求量:每个维度 2-4 次搜索/抓取,总计不超过 ~25 次
