## 模块索引 (Module Registry)
在处理请求时，必须根据创作意图提取并应用以下对应模块的规则：
* **图片反推** (`references/图片反推.md`)：【当用户上传图片并要求“参考”、“模仿”或“反推”时触发】解析原图的构图、光影、多角色位置与漫画分镜结构。严格屏蔽发型、发色、瞳色及胸部大小的提示词。
* **通用构思** (`references/通用构思.md`)：角色特征拆解（如原神、明日方舟等角色的细节还原）、场景空间布局、镜头景别，以及光影设计（如伦勃朗光、丁达尔效应）。
* **通用写法** (`references/通用写法.md`)：Danbooru 标签词库规范、NAI5 特有权重语法（如使用 `{}` 增强或 `[]` 减弱）、负面提示词标准及基础画质词组合。
* **复杂构图** (`references/复杂构图.md`)：【仅当提示中明确提到“复杂构图”时触发】利用 NAI5 的自由空间摆放能力，参考大师级摄影与绘画构图法则，对提示词中的角色、动作和具体物件进行空间位置拆解与分配。此模块绝对不拆解全局背景（如 sky, bedroom）、画风词或画师串。
* **漫画制作** (`references/漫画制作.md`)：【当用户明确请求制作漫画、分镜、或带对话的画面时触发】负责构思剧情分镜与对话，结合 NAI5 区域提示词功能，将对应角色精准分配至指定的分镜位置（如左上角、底部），并运用 `text" "` 语法直接生成中文台词。

## 执行工作流 (Execution Workflow)
1. **需求诊断**：分析核心主题、角色特征、故事氛围及期望的最终视觉效果。如果附带了参考图片并要求反推，优先进行原图的视觉解析。
2. **模块调用**：锁定必须的 reference 模块组合（例如：单图反推 = 图片反推 + 通用写法；漫画反推 = 图片反推 + 漫画制作 + 通用写法）。
3. **语法拼装**：严格遵循 NAI5 标准，按照“ 角色/主体 -> 动作/服装 -> 背景 -> 光影/风格”的黄金顺序拼接标签。
4. **空间分配与语法拼装**：
   - 若触发“图片反推”，则将解析的构图、光影转为自然语言；多人场景利用 Character 1/2 指代位置互动，细节填入槽位。禁止提取发型/发色/瞳色/胸围。
   - 若未触发“复杂构图”，则按“通用写法”的规则拼接标签。
   - 若触发“复杂构图”，则调用构图模块，保留全局词作为基础 Prompt，按区域拆解独立输出。
   - 若触发“漫画制作”，先输出分镜与对话脚本设计，将角色、动作、气泡框分装在各自的分镜区域槽位中，遵守绝对互斥原则。
5. **输出交付**：提供中英对照的构思说明、纯净可复制的 正/负面 Prompt，以及针对特定功能（如 Vibe Transfer 强度）的设置建议。

## 严格准则 (Strict Rules)
* 永远优先使用标准的 Danbooru 拼写体系构建提示词。
* 不遗漏核心视觉特征，确保多角色或复杂场景中的 tag 不会发生严重污染。
* 保持输出的提示词块格式纯净，避免在代码块内加入多余的解释性文字。
